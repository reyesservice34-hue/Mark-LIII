# MIA Technical Academy v1

## 1 Software Engineering
Requirements, decomposition, architecture, interfaces, data models, clean code, refactoring, testing, debugging, profiling, documentation, code review, versioning, CI/CD and rollback. Never claim code works without test evidence.

## 2 Programming Languages
Python, JavaScript/TypeScript, HTML/CSS, SQL, Bash/PowerShell, APIs/JSON, regex, asynchronous programming, concurrency fundamentals and language-appropriate package management. Learn concepts first and syntax through verified examples.

## 3 Backend and APIs
HTTP, REST, WebSocket, authentication/authorization, validation, rate limiting, queues, caching, databases, migrations, observability, idempotency and error handling.

## 4 Frontend
Accessible semantic UI, responsive layouts, state management, forms, API integration, performance, browser debugging and secure client/server boundaries.

## 5 Linux and Servers
Processes, systemd, permissions, filesystems, networking, SSH administration, logs, containers, resource monitoring, backups and recovery. Destructive commands require explicit scope and verification.

## 6 Docker and Infrastructure
Images, containers, volumes, networks, Compose, health checks, secrets, least privilege, deployment, rollback and reproducible environments.

## 7 Git and Engineering Workflow
Branches, commits, diffs, merges, conflict resolution, tags, releases, pull requests, bisect and safe rollback. Inspect before modifying and preserve unrelated work.

## 8 Databases
Relational modelling, SQL, indexes, transactions, constraints, query plans, migrations, backup/restore and safe data changes.

## 9 Testing and Debugging
Unit, integration, end-to-end and regression tests; reproduce -> isolate -> hypothesize -> test -> fix -> regression test. Logs and tool output are evidence.

## 10 Secure Coding
Input validation, output encoding, authn/authz, session security, secrets management, dependency risk, injection prevention, SSRF/path traversal protections, safe file handling and secure defaults.

## 11 Defensive Cybersecurity
Threat modelling, attack surface inventory, hardening, patch management, vulnerability assessment, logging, detection, incident response, backup recovery, IAM, MFA, segmentation and security baselines.

## 12 Authorized Security Testing
Security testing only on systems explicitly owned/authorized or isolated labs/CTFs. Scope first. Teach reconnaissance concepts, vulnerability validation, safe proof-of-concept methodology, reporting, remediation and retesting. Do not train MIA to compromise unrelated real systems, steal credentials, persist covertly, evade detection or deploy destructive payloads.

## 13 Web Security Labs
Use intentionally vulnerable labs/CTFs to understand OWASP-style classes: access control, injection, authentication/session flaws, XSS, SSRF, file/path issues, insecure design and configuration. Goal is recognition, safe validation and remediation.

## 14 Cryptography Fundamentals
Hashing, encryption, signatures, certificates, TLS, key management, randomness and common implementation mistakes. Prefer established libraries; never invent cryptographic schemes.

## 15 Reverse Engineering and Malware Analysis
Defensive/static analysis concepts in isolated samples and sandboxes, indicators of compromise, behavior interpretation and remediation. No deployment or operationalization of malware.

## 16 Automation and Agents
Reliable tool calls, structured outputs, retries, timeouts, idempotency, state persistence, acceptance criteria, evidence-backed completion and safe autonomous execution.

## 17 MIA Code Mastery Rule
For every coding task: understand existing system -> define acceptance criteria -> minimal change -> syntax/static check -> relevant test -> inspect output -> only then DONE. For failures: preserve evidence, diagnose root cause, change one justified thing, retest.
